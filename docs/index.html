Python 库 · stage runner

按阶段处理一批结构相同的目录

许多相似的对象收成目录，再沿一张有向无环图逐段转换。算子只描述转换。输出放在哪一次运行里，由这次运行决定。

背景

进度记在每个对象自己的目录里。一段等上一段结束，段内只补没做完的、重做上游变了的。

1 一批相同的对象

一张张表、一个个模型，走相同的几步：取得源文件，渲染提示词，调用模型，留下结果。

2 调用慢，而且会停在半路

令牌用尽、进程退出、外部命令返回错误，都可能发生在几千个对象已经处理了一部分之后。

3 算子可以换一次运行再用来

算子描述转换，不描述这次的输出位置。输出目录和要覆盖的参数，在组装作业时再填上。

工作是怎么组织的

实体是一层子目录

目录名就是实体名。名字不能含斜杠，也不能以 . 或 _ 开头。data 是正文，tag.json 是给下游过滤和填模板的特性，有上游时还含 upstream 快照。图的起点没有上游，因此不写这个键。

20261015 是这次运行的 epoch，也就是实体所在的那层子目录名。换一个 epoch 等于换一个子目录，上一次的结果留在原处。

runs/
├─ tables/                 source
│  └─ 20261015/orders/
│     ├─ data             正文
│     └─ tag.json         特性
└─ prompt/                 map
   └─ 20261015/orders/
      ├─ data
      └─ tag.json         含 upstream

四种对应

算子的静态文件放在 home 里，由 DOCORDER_HOMES 搜索，靠前的同名目录优先。props.json 里的 type 和 class 必须书写，作业不能改。class 写成 模块:类名，或写成 primary:类名 以加载 home 里的 primary.py。parallelism 和 retry 也可以写在 home 里，添加节点时可以覆盖。找不到外部程序不会重试；程序返回非零状态时，按 retry 再执行该实体。包内可以直接配置的 function 是 source 和 map，后两种类型已有基类。

作业是一张图

每个节点有名称、算子 home、本次输出路径。输出路径不写进 home。除 source 以外，每个节点声明一个上游。runner 按拓扑顺序执行，一个节点全部结束才开始下游。书写顺序用来排定互不依赖的节点谁先谁后。

安装

Python 3.10 或更高版本，以及 uv。PyPI 上还没有这个包，从仓库安装。装上的是库和 function 类。算子 home 由调用方放到 DOCORDER_HOMES 里，不随包分发。

git clone https://github.com/jixie-wish/docorder.git && cd docorder && uv sync

Jinja2 随安装装上 JsonnetToPrompt 需要本机 jsonnet PromptToLLM 的工具由你在 home 的 tools/ 里定义

用法

两个 home 能被 DOCORDER_HOMES 找到，再在脚本里连成作业。各 function 的参数见 functions.md。

runs/tables/20261015/… runs/prompt/20261015/…

directory 的相对路径相对算子 home 解析。每个直接子文件成为一个实体，名字是去掉最后一个后缀的主名，正文是文件原文。source 只在 start_from_scratch=True 时按目录重写；否则下游读取输出路径上已经存在的实体。config 可以覆盖 home 里的同名 function 参数。parallelism 大于 1 时 runner 在当前进程里用线程分片，不另起子进程。

同一 epoch 再跑

runner 把应得名单和磁盘上的目录做比较。模型调用按 home 里的 retry 在本段内重试；重试耗尽后，已写好快照的实体留下，下次从其余实体继续。

orders
  • tag.json 的 upstream 仍吻合
留下

快照里的上游哈希和 epoch 都与当前一致。

items
  • 没有快照，或哈希变了
执行并覆盖

名单里有，但还没完成；或上游正文已经变了。

draft
  • 名单里已经没有
删除

目录里还在，应得名单里已经没有这个名字。
