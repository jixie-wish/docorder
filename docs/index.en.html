Python library · stage runner

Process a batch of same-shaped directories, one stage at a time

Similar objects become directories, then move along a directed acyclic graph one stage at a time. An operator describes the transform. Where this run writes is decided by the run.

Background

Progress lives in each object's own directory. A stage waits for the previous stage, then fills in what is unfinished and redoes what the upstream changed.

1 A batch of same-shaped objects

Tables or models pass through the same steps: take a source file, render a prompt, call a model, keep the result.

2 Calls are slow, and they stop halfway

A token limit, a process exit, or a non-zero command can happen after thousands of objects are already done.

3 Operators outlive one run

An operator describes a transform, not this run's output path. The output directory and any overrides are filled in when the job is assembled.

How the work is organized

An entity is one directory

The directory name is the entity name. It cannot contain a slash, and it cannot start with . or _. data is the body, and tag.json holds traits for filtering and templates. When the entity has an upstream, the snapshot lives in tag.json as upstream. The start of the graph has no upstream, so it does not write that key.

20261015 is the epoch of this run, the subdirectory that holds the entities. A different epoch is a different subdirectory. The previous result stays where it is.

runs/
├─ tables/                 source
│  └─ 20261015/orders/
│     ├─ data             body
│     └─ tag.json         traits
└─ prompt/                 map
   └─ 20261015/orders/
      ├─ data
      └─ tag.json         includes upstream

Four correspondences

An operator's static files live in a home found through DOCORDER_HOMES. A home earlier in the list wins. type and class in props.json are required, and a job cannot change them. class is module:Class, or primary:Class to load primary.py in the home. parallelism and retry may also be written in the home, and adding a node can override them. A missing external program is not retried. A non-zero status runs that entity again according to retry. The functions that can be configured directly are source and map. The other two types have base classes.

A job is a graph

Each node has a name, an operator home, and an output path for this run. The output path is not stored in the home. Every node other than a source declares one upstream. The runner executes in topological order. A node finishes completely before its downstream starts. Declaration order decides which of two independent nodes runs first.

Install

Python 3.10 or newer, and uv. The package is not on PyPI yet, so install it from the repository. The install provides the library and the function classes. Operator homes are directories you place on DOCORDER_HOMES. They are not shipped in the package.

git clone https://github.com/jixie-wish/docorder.git && cd docorder && uv sync

Jinja2 comes with the install JsonnetToPrompt needs a local jsonnet PromptToLLM tools are defined by you in the home's tools/

Usage

Both homes must be visible to DOCORDER_HOMES, then a script joins them. Function parameters are in functions.en.md.

runs/tables/20261015/… runs/prompt/20261015/…

A relative directory is resolved against the operator home. Each direct child file becomes one entity. The name is the stem with the last suffix removed, and the body is the original file text. A source rewrites from the directory only when start_from_scratch=True. Otherwise downstream reads the entities already at the output path. config may override same-named function parameters from the home. When parallelism is greater than 1 the runner slices the work across threads in the current process and does not start worker processes.

Running the same epoch again

The runner compares the expected names with the directories on disk. A model call retries inside the stage according to retry. After retries are exhausted, entities that already have a snapshot stay, and the next run continues from the rest.

orders
  • tag.json upstream still matches
Stays

The recorded upstream hash and epoch both match the current upstream.

items
  • no snapshot, or the hash changed
Run and overwrite

Expected, but not finished yet, or the upstream body has changed.

draft
  • no longer on the list
Deleted

Still on disk, and no longer in the expected names.
